# Why GenHTTP is god tier — the layout

An internal explainer of [GenHTTP](https://github.com/Kaliumhexacyanoferrat/GenHTTP) v11.1,
the pure-C# webserver, with its new **Ioxide** engine: what the machine actually is, part by
part, and why each part is the right part.

Every claim here was read out of the source tree (`Kaliumhexacyanoferrat/GenHTTP`, branch
`main`, October 2026). File paths refer to that repo. Each topic below has its own companion
doc (`docs/NN-*.md`) and an interactive isometric figure in `figures/NN-*/index.html` —
open the built pages in a browser; they were drawn with the
[Anatomy](https://github.com/wheresryan22/anatomy) kit.

---

## The one-paragraph claim

GenHTTP is a 17-year-old MIT-licensed webserver in pure C# that, in 2026, runs the *same
application* on three swappable engines — a threaded HTTP/1.1 engine for embedding, Kestrel
for the edge, and **Ioxide**, a Linux engine built on a native `io_uring` core with kernel
TLS (kTLS), zero-copy sends, SNI, mutual TLS, live certificate rotation and HTTP/1.1 +
HTTP/2 + HTTP/3 (QUIC over ngtcp2/nghttp3). Under that sits an allocation-free request
pipeline (pooled requests, zero-copy `ByteString` views generated by a Roslyn source
generator, a hardened HTTP parser called Glyph11), a composable handler tree with an
onion-style concern chain, a reflection mapper that compiles your service methods into
typed endpoints (with interceptors and OpenAPI schemas generated from the same reflection
model), and ~1,600 acceptance tests that run **every** test against **every** engine on a
six-OS CI matrix. Few web servers in any language offer this combination; almost none
offer it with this degree of verification.

## The evidence table

| Claim | Evidence in the tree |
|---|---|
| Allocation-free pipeline | README: *"In 2026, the API and internal engine have been rewritten to be allocation-free."* Pooled `Request`/`Response`/`ClientContext` (`Engine/Shared/Types/`), `StreamedRequest` pooled per reactor at max 1024 (`Engine/Ioxide/Protocol/Requests/StreamedRequest.cs`): *"a whole exchange allocates nothing."* |
| Zero-copy parsing | `Glyph11.Parser.UltraHardened` parses headers straight into memory views; `[MemoryView]` source generator (`Generators/MemoryView/`) emits `ByteString`, `ContentType`, `HttpProtocol`, `PathSegment`, `RequestMethod`, `AlgorithmName` — structs over chunks of the request buffer with precomputed hashes. |
| io_uring engine | `Engine/Ioxide/` + NuGet `ioxide 0.15.251` (+ `.http2`, `.ngtcp2`, `.nghttp3`). One `Reactor` per core thread (`Server.cs`), ring of 8192 entries, 32 KiB × 4096 recv slots, 16 KiB write slabs, optional `ZeroCopySend` (`EngineOptions.cs`). |
| Kernel TLS offload | `TcpTransportOptions.TxKernelTls / RxKernelTls` (kTLS, opt-in), OpenSSL-backed user-space TLS otherwise, SNI, mutual TLS validators (`TcpDriver.Accepts`), live certificate rotation (`CertificateRotationSample`, `SIGHUP`). |
| HTTP/3 | `Http3Driver` over `Nghttp3Connection`; QUIC transport with peer-migration pinning and datagram routing (`QuicTransportOptions`); QPACK tuning (`Http3Options`). |
| One app, three engines | `ServerEngine` enum: `Internal`, `Kestrel`, `Ioxide`; meta-packages `GenHTTP.Core{,.Kestrel,.Ioxide}` differ only in the engine dependency. README: *"Engines are tested to be compatible with all modules, so you can switch the runtime without any further adjustments."* |
| Engine-parity testing | `Testing/Acceptance/MultiEngineTest.cs` — an `ITestDataSource` running every test against Internal, Kestrel and (on Linux) Ioxide; ~1,600 test attributes across 174 test classes; CI enables `io_uring`, `modprobe tls`, and libmsquic on the runner. |
| Six-OS CI matrix | `.github/workflows/build.yml`: ubuntu x64 + arm64, windows x64 + arm64, macos x64 + arm64; SonarCloud gate; `TreatWarningsAsErrors=true` repo-wide. |
| Live performance monitoring | HTTP Arena badges on each engine row of the README; BenchmarkDotNet harness (`Benchmarks/`) drives raw HTTP/1.1 byte strings through the *real* parser and handler pipeline (`BenchmarkContext`). |
| DX | `Inline.Create().Get((int a, int b) => a + b)` + `.AddOpenApi().AddScalar()` is a complete service; `ServiceResource.From<T>()`, `Controller.From<T>()`, DI integration, nine Ioxide samples (`Playground/Samples/Ioxide/`). |

## The architecture, laid out

```
                        your application code
                                 │
        ┌────────────────────────┴─────────────────────────┐
        │  builder facade                                   │
        │  Inline / ServiceResource / Controller / Layout / │
        │  Files / Proxy / LoadBalancer / Websocket / SSE   │   Modules/*  (31 projects)
        └────────────────────────┬─────────────────────────┘
                                 │  IHandlerBuilder.Build()
        ┌────────────────────────┴─────────────────────────┐
        │  handler tree of IHandler                          │   API/General/Content
        │  concerns wrap handlers: first added = outermost   │   IConcern : IHandler { Content }
        │  root = CoreRouter( ServerCompliance → Error →     │   Engine/Shared/Hosting/ServerHost.cs
        │                     user concerns → logging )      │
        └────────────────────────┬─────────────────────────┘
                                 │  ValueTask<IResponse?> HandleAsync(IRequest)
        ┌────────────────────────┴─────────────────────────┐
        │  engine (pick one, same IServerHost API)           │
        │  ┌──────────┐ ┌──────────┐ ┌────────────────────┐ │
        │  │ Internal │ │ Kestrel  │ │ Ioxide             │ │
        │  │ H1.1     │ │ H1/H2/H3 │ │ H1/H2/H3, io_uring │ │   Engine/*
        │  │ threaded │ │ ASP.NET  │ │ kTLS, mTLS, QUIC   │ │
        │  └──────────┘ └──────────┘ └────────────────────┘ │
        │  shared: pooled Request/Response, Glyph11 parse,   │   Engine/Shared
        │  ResponseSerializer, sinks, keep-alive loop        │
        └────────────────────────────────────────────────────┘
```

The eight topics, each with a figure:

1. **The Ioxide core** — one io_uring reactor per core, ring entries, trunks for TCP/kTLS and
   QUIC. *Fig 1 — the telephone exchange.* → `docs/01-the-iooxide-core.md`
2. **The zero-alloc exchange** — bytes in, request parsed into pooled views, handler tree,
   response serialized to sinks, keep-alive loop. *Fig 2 — the coin sorter.* → `docs/02-the-zero-alloc-exchange.md`
3. **The handler tree** — `IHandler` all the way down; layout routing; `null` means 404.
   *Fig 3 — the signal box.* → `docs/03-the-handler-tree.md`
4. **The concern chain** — middleware as wrappers: compliance, errors, compression, auth,
   caching, logging — folded around the tree. *Fig 4 — the filter stack.* → `docs/04-the-concern-chain.md`
5. **The reflection mapper** — attributes to operations; argument binding precedence
   (path → injected → streamed → body → query → content); Roslyn-compiled delegates with a
   reflection fallback; interceptors. *Fig 5 — the card catalog.* → `docs/05-the-reflection-mapper.md`
6. **The OpenAPI generator** — explorers crawl the *real* handler tree; schemas come from the
   same serializer settings you serve with. *Fig 6 — the surveyor.* → `docs/06-the-openapi-generator.md`
7. **Freshness & size** — ETag validation (`If-None-Match` → 304), expiry policy, brotli/gzip/
   zstd, precompressed assets. *Fig 7 — the cloakroom.* → `docs/07-freshness-and-size.md`
8. **The turntable** — three engines, one application; what it takes to make that honest.
   *Fig 8 — the engine turntable.* → `docs/08-the-turntable.md`

## What the numbers say

- **Version**: 11.1.0 (`Directory.Build.props`), targeting `net10.0;net11.0`, C# 14,
  `runtime-async=on` on net11, warnings as errors, deterministic builds with SourceLink.
- **Footprint of the core meta-package**: `GenHTTP.Api` + one engine + `Practices` + `IO` +
  `Layouting` — everything else is opt-in modules; `GenHTTP.Full` adds all 31.
- **Tests**: 2 test projects, 198 files of acceptance tests, ~1,600 test attributes, all
  engine-parameterised where they touch the wire.
- **CI**: `build.yml` (SonarCloud + tests + 6-OS verify matrix) and `release.yml`
  (packs and pushes the 6 meta packages to NuGet).
- **History**: born 2008 to run on an Intel Atom netbook; API-development focus since 2024;
  engine + API rewritten allocation-free in 2026; Ioxide landed 2026-06-22 and reached
  HTTP/1.1→HTTP/3 with native TLS, SNI, mTLS and cert rotation within the same year.

## Honest limits (also part of god tier)

The docs say *where* things are true, not just that they are true: kTLS is off by default and
"is not a free win" (Ioxide README); the idle-timeout default is 0 because the transport
cannot tell an idle websocket from an idle keep-alive, "so the framework does not guess on
your behalf" (`TcpTransportOptions.IdleTimeoutMs` remarks); there is no server-side content
cache module — freshness is validation-based (ETag), which is the correct default; the
load balancer is priority-groups + random, not round-robin, and says so. A codebase that
documents its own trade-offs is rarer than one with a fast benchmark.
